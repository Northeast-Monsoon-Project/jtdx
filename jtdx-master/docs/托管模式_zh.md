# JTDX-F 托管模式

在“文件 → 设置 → 托管模式”分别设置 DXCC猎人和 QSO爱好者；此页位于过滤之后、计划程序之前。主菜单的托管模式位于自动程序之后、DX远征之前。

主菜单中的 DXCC猎人、QSO爱好者、关闭互斥。每次启动均为关闭，不记忆上次开启的模式。设置页中的目标条件和呼叫次数会保存；失败重试记录只保留到软件退出，切换托管模式不会清空它们。

选择模式后先监听，仍需人工启用发射才能进行呼叫和定时 CQ；也可在开启相应设置后双击有效呼号来启用。切换或关闭托管模式会停止当前发射；开始新会话需要重新人工启用。监管到期后只完成当前 QSO 或达到适用的呼叫次数限制，随后停止；没有当前 QSO 时立即停止。人工停止、故障停止始终立即执行。停止后定时任务不会重新开启发射。DX远征与托管模式互斥，WSPR 和 JTTY 不使用托管选台，FT2 可使用。

## 目标与来电

DXCC猎人可选新CQ分区、新ITU分区、新DXCC、新波段&模式DXCC、新网格；QSO爱好者可选新呼号、新波段&模式呼号。勾选多个条件时，满足任意一个即可成为主动呼叫对象；全部取消时仅回答符合设置的来电和发送规定的周期 CQ。默认勾选各自全部目标条件。

“新”依据当前操作员加载的日志历史判断，新网格使用四字符网格。同波段和模式分别匹配，不把其他波段或模式的通联当作本波段本模式已完成。正在与他人交换报告的电台不会被主动呼叫；CQ、73、RR73、RRR 可成为候选，定向 CQ 须适合本台。

V3.6.5 起，新自动外呼只使用报文 UTC 所属的当前时隙或紧邻前一时隙的邀请，包含 CQ 和其他电台的 73/RR73/RRR；不会再主动回答三四轮前的旧 CQ。FT8、FT4、FT2 分别按 15、7.5、3.75 秒周期恢复报文时隙，并处理跨午夜日期。有效期由消息时间决定，迟到的解码结果不会变成新邀请；同一呼号的旧结果也不能覆盖更新状态。全双工可使用当前时隙已解出的候选。

上述有效期只限制发起新自动外呼，不取消发给本机的来电排队，不中断已有 QSO，也不禁止人工双击旧解码行；这些情况继续遵守各自的授权、通联次数、监管和黑名单规则。有效发射时隙内允许中途起发的行为不变。

来电优先于主动寻找新目标。“回答曾经通联过的呼号”默认关闭；开启后，同波段和模式已经通联过的电台再次呼叫本台也会得到应答。此设置不会让托管模式主动重复呼叫所有已通联电台。

候选排序：新CQ分区 → 新DXCC → 新波段&模式DXCC → 新ITU分区 → 新网格 → 新呼号 → 新波段&模式呼号；同级先选择信噪比高的电台。排序按电台具备的新项目判断，是否入选则按当前模式勾选的条件判断。

自动选择时，正在进行的 QSO 不会被其他候选打断；完成后先处理仍在等待的来电，再寻找新目标。没有目标时监听，不发送普通自动程序中的空闲 CQ。普通自动程序的单次通联、选择优先级和呼叫计数不控制托管模式。

“设置 → 程序 → 对方回应其他电台时暂停呼叫并等待”是普通 AutoSeq 的等待/恢复选项，不控制托管模式。托管继续按自身候选条件、当前 QSO、各消息类型次数和失败重试规则处理，不把这个开关当作解除托管上限的条件。

## 人工选台与发送时机

V3.6.5 起，已经人工启用发射的托管会话中，可用鼠标左键双击解码栏中的有效呼号来指定或更换目标。目标不必满足当前模式的“新”条件；即使默认关闭的“双击呼号启用发射”未勾选，也可在这个已授权的会话中选台。界面 DX 信息与托管实际目标同步更新，随后按托管的消息次数、通联结束确认和监管规则处理。重复双击同一在途目标不会重置次数。

这项操作不能绕过停止状态：TX 未启用时，仍需先点击“启用发射”，或明确勾选“双击呼号启用发射”再双击。正在准备发射、PTT 已开启或音频正在发送时禁止换台；自身消息、无效呼号和永久黑名单检查仍有效。人工停止撤销授权，后续解码或旧回调不能自行重新开启。

托管在本机发射时隙内用当时已解出的候选进行选择，不再一律等到整批解码结束；已有候选仍按来电优先、新项目顺序和同级信噪比排序。没有候选时继续监听，不为赶时间临时发送 CQ；下面的独立周期 CQ 计划保持不变。

继续允许在有效时隙中途起发，并沿用既有时序同步，不增加首秒截止或跳过本轮的限制。CAT/PTT 安全确认与超时没有为缩短等待而放宽，中途起发仍可能缺失部分音频前部，不保证零截断。自动目标切换仍遵守“自由切换时序”的条件与 5 分钟冷却，人工选台按原人工切换规则处理。

V3.6.5 同时减少分频与校准频率未变化时的重复 CAT 状态请求。已确认这些冗余请求及等待整批解码的路径，但尚未确定现场 6～7 秒具体耗在哪个环节，不将它归因为深度解码或宣称已经消除。当前呼号日志目录中的每月 `yyyyMM_TX_TIMING.TXT` 独立记录“Managed selection timing”和“TX start timing”，用于定位慢选台以及从 PTT 请求到确认、音频请求和 GUI 观察到本次音频源首样本回调的耗时；超过 1 秒或开启已有解码调试记录选项时写入。首样本绑定本次发送代次，旧回调不计入，也不等于实际 DAC/RF 起发。停止前若 PTT/音频尚在处理中且未观察到本次首样本，同样条件下补写 `phase=cancelled`。这些诊断使用单线程后台写入，最多 64 条待写任务，写入失败或积压已满则丢弃诊断，不弹错误框、不阻断发射；记录阈值不限制发射。详见使用说明的故障排查部分。

## 定时 CQ 与呼叫次数

两种模式均强制开启“每15分钟发送三轮CQ”，复选框选中并灰显。周期 CQ 独立按每批累计 3 轮执行，不受下面的 QSO 消息次数上限影响。无人呼叫时最多连续发送这 3 轮；每轮之间仍正常接收。

人工启用发射后开始计时，首次等待 15 分钟；到期时若正在通联，先完成通联。发出 CQ 后收到来电先应答，连续来电继续优先，之后只补足本批尚未发送的轮数。例如已发 1 轮 CQ 后完成一个或多个 QSO，只需补剩余 2 轮，不从头重新发 3 轮。本批累计发完 3 轮后开始下一个 15 分钟间隔，不积攒错过的多个批次。

呼叫次数可选 0～99，默认 3；0 表示 QSO 消息不因次数限制放弃，周期 CQ 仍固定按每批累计 3 轮执行。V3.6.4 起，初始呼叫、报告、R 报告、RRR、RR73 和 73 各有独立的发送额度。同一 QSO 中首次使用某类消息时从第 1 次开始，切回已经使用的类型则保留已发次数。重复回应、再次双击同一在途目标或此前回应过一次，都不会清零额度或永久解除限制。

例如上限为 3：初始呼叫第 2 轮收到回应并开始发送报告后，报告消息拥有自己的 3 次机会；此时若切回初始呼叫，之前发出的 2 次仍保留，只剩 1 次。若一种消息发满 3 次仍未取得进展，则在给对方下一接收周期的回应机会后放弃。实际通联已正常推进或确认完成时，不会被另一类消息耗尽的计数误停。

次数检查也在开始发射前执行。第 3 轮后即使解码仍忙，也不能继续发送第 4 轮同阶段消息；程序先等待接收结果，再决定进入下一阶段或放弃。计数来自实际完整发送，选中消息或仅准备 PTT 不算一轮。

RR73/73 仍遵守完整的结束确认：本机发 RR73 后等待对方 73；本机发 73 后等待一个完整接收与解码周期，且未再次收到对方 RR73。发送波形正常结束并释放 PTT 后，才可完成或按次数判定失败。RR73 与 73 分别计数，互相切换也保留各自已发次数；两者使用当前托管模式自己的上限，普通自动程序中的四类发送次数不控制它。

- DXCC猎人达到阶段上限仍未取得进展：忽略该呼号 10 分钟。
- QSO爱好者首次失败：忽略 10 分钟；第二次失败：忽略 30 分钟；第三次失败：本次运行不再主动呼叫，重启清零。

等待时间到期后必须再次收到该电台可应答的消息才会重新尝试，不使用过期解码盲目呼叫。主动呼叫的忽略名单不阻止对方随后主动呼叫本台；来电仍按“回答曾经通联过的呼号”设置处理。

失败后的忽略名单仅影响托管的自动主动呼叫，不隐藏译码，不写入永久黑名单。普通模式新增的 8 分钟重呼间隔与这些托管重试记录独立。

使用 TCI 并选择“Fake It”分频方式时，V3.6.4 同时补齐该转接路径的音频与波形事件转发，供实际发送计数和结束确认使用。它是独立的转接路径修复；FT-450 使用本地声卡时的多发问题应按上述发射前次数检查处理。

## 显示

“显示通知 → 曾经通联 → 隐藏不显示”默认不勾选。首次升级 V3.3.0 会将旧版可能错误保存的默认值纠正为不勾选，之后保存操作员的手动选择。开启后隐藏普通已通联消息，但保留当前 QSO 以及发给自己的报告、RRR、RR73、73 等消息。托管模式的日志判断与此显示开关独立。
