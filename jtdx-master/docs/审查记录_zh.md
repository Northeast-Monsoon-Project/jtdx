# JTDX-F V3.4.0 审查与验证记录

审查基线：用户提供的 JTDX 2.2.159 源码；修改日期：2026-10-30。仓库保留原始导入提交，可用 `git diff` 对照修改。

## 结论的范围

已对项目 C/C++ 源码进行全库静态扫描（第三方 contrib 与文档单独视为外部代码），并人工检查通联状态机、发射监管、音频文件、网络控制、进程管理、日志和解码相关边界；同时进行 Linux 和 Windows 目标编译。Fortran 部分结合编译诊断、边界检查和合成 FT8 解码进行验证。

静态工具的告警数不能直接作为 bug 数：Qt 宏、聚合初始化、在使用前才设置的状态、第三方结构和未启用的实验代码会产生误报或需要上下文判断。本次没有把告警清零作为“无 bug”证明，也不声称已经证明每条代码路径、所有硬件及长期运行都正确。

## V3.3.0 托管与显示

- 修复未保存 `workedDontShow` 时实际字段未初始化的问题，默认不隐藏已通联电台；勾选后按同波段和模式的通联记录隐藏普通消息，保留当前 QSO 及发给自己的消息。
- 托管模式独立选择目标，使用日志数据判断新分区、DXCC、网格、呼号；不依赖通知着色或普通 AutoSeq 的选择条件。隐藏消息仍可用于托管通联状态，显示过滤不阻断应答。
- 模式、呼叫失败次数、忽略名单和 CQ 计划仅保存在内存；模式重开默认关闭。忽略计时和周期 CQ 使用单调时钟，不受 UTC 校时影响。
- 人工发射许可和监管计时器继续生效，空闲监听不会发送普通 AutoSeq 的 CQ；周期 CQ 等当前 QSO 结束，有人应答时优先处理，剩余轮数随后补足。
- 呼叫次数按实际发射轮数累计；已有回应的通联不按“无人回应”处理。完成后重新检查日志中的新项目，优先响应排队来电，最后返回监听。
- 修复连续解码交接的竞争：原先子进程通知完成后再等待 GUI 创建锁，下一次请求可能提前删除该锁，导致子进程一直等待、界面停在解码中。现在子进程先建立空闲锁再通知完成，下一请求直接解除等待；增加连续六次真实 FT8 WAV 解码检查。
- 安装验收中复现启动随机种子读取死循环，调试栈定位到 `init_random_seed`。原代码未终止 EOF/错误读取，短读还会按整数而非字节移动指针，可能越界。Windows 改用本机 `rand_s`，POSIX 按字节累计、错误/EOF 回退；增加短读、EOF、错误、EINTR 和相邻内存保护测试。

## V3.2.0 新功能与边界检查

- 50 个 NTP 地址按地区合并排列、亚洲在前，同一服务商最多两个公开地址；检查地区/服务商覆盖及域名解析。校时间隔提供 10 档、默认 15 分钟，检查设置保存/重启恢复、非法值回退，以及移除的预设自动保留为自定义地址。
- NTP 客户端校验包长度、版本、模式、同步状态、stratum、请求标识、时间戳、往返延迟和时间不确定度；处理 2036 年 NTP 秒计数回绕；拒绝请求期间系统时钟发生跳变的样本。
- 系统 UTC 校时与用户时区分离；跨 UTC 午夜、UTC+8、UTC−4 的模拟验证。发射/PTT 时暂缓。
- 独立权限辅助进程只接收服务器设置，不接受任意命令或由普通进程传来的任意时间戳；仅监听本机临时端口，通过每次运行随机令牌建立会话。关闭连接、程序退出或心跳失联后退出。网络与系统权限错误均可见。
- Windows 授权提示尚未结束时关闭并重开校时，会等待旧提示结束再发起新会话；旧会话的拒绝不会误伤新会话，已加入回归。
- 日志读取/转换移到后台，完成后在主线程替换历史快照，丢弃已切换呼号的过期结果；处理结束或异常时关闭等待弹窗。
- 使用逻辑 busy 标记，避免 future 已完成而 finished 通知尚未处理时复用 watcher。目录监听忽略锁文件/临时文件变化，防止重载循环。
- 安装脚本显式使用 UTF-8 BOM 与 `-INPUTCHARSET UTF8`，修复旧版降级确认中文被按 ANSI 代码页读取的乱码；增加对弹窗完整 Unicode 文本的检查。
- 定时 CW 配置入口隐藏，旧 IDint 强制归零，CW 发射长度清零。

## V3.1.1 修订

- 修正设置读取仍默认 `LockTxFreq=true` 的遗漏，默认改为 Tx/Rx 异频。首次升级会纠正旧版保存的锁定状态，之后保存并恢复操作员的手动选择。
- 移除呼号管理顶部的说明文字，保留资料列表和管理按钮。
- 使用真实主界面检查首次启动、Rx/Tx 频率独立调整、旧设置迁移，以及手动选择的保存/恢复；复用呼号管理流程和截图检查。

## V3.1.0 新增审查和修复

| 范围 | 确认的问题或本轮防护 | 处理与验证 |

| 呼号切换 | 开启连续发射后，在两个发射时隙之间修改呼号可能混用资料及日志 | 整个启用发射会话、调谐及实际 PTT 期间锁定呼号选择和管理 |
| 自动程序 4+ | CQ 候选受旧计数条件限制，结束消息分类依赖显示选项；历史清空后同一解码周期的时间未恢复 | 移除强制先 CQ 条件；将合规的 73、RR73、RRR 作为新通联候选；每次解码设置历史时间；经真实消息分类路径验证 |
| FT8 解码容量 | 200 条消息、频率、信噪比及时间偏差数组缺少容量保护，统计写入存在并发竞争 | 有界写入、OpenMP 同步；8 线程共 10,000 次写入并启用 Fortran bounds 检查 |
| ADIF 解析 | 按行及查找标签不能可靠处理多行备注、备注内的标签；小写呼号、仅含频率的旧记录可能漏掉历史匹配 | 按字段长度解析；规范化呼号和频段；从 FREQ 推导缺失的 BAND；历史查询共用解析结果 |
| 季度导入失败 | 多季度写入中断、重复导入、备份目录创建失败可能造成重复或丢失原件 | 每季度原子替换和去重；全部写入成功后才备份；备份失败不删除原件；故障重试回归 |
| 日志写入失败 | 保存失败后仍继续按已记录的通联处理 | 写入失败保留未完成状态并提示；追加失败尝试恢复原长度；与后台导入共用目录锁 |
| SuperFox 模式 | 传统 Hound 跳频规则不适用于 SuperFox | 独立接收选项，禁用传统 Hound 向下跳频；模拟 SuperFox WAV 经 GUI 和共享内存交给实际解码器验证 |

呼号管理、季度目录、默认选项、菜单精简、品牌图标与安装器升级/降级属于新功能和行为调整，不全部算作原版 bug。新增代码同样经过上述失败路径检查。

SuperFox 使用 GPL 来源及独立测量的编码表，来源、提交和测量记录见 `lib/superfox/PROVENANCE.txt`。当前实现接收解码及普通 FT8 Hound 应答，不包含在线 OTP 身份认证；接收到签名消息也不会标记为“身份已验证”。

## 验证内容

- Linux 的真实 Qt 主界面回归：连续 QSO 三种完成状态、来电/CQ/空闲分支、奇偶时隙、单次通联、最终消息不打断、监管 0/1/999 分钟、活动不重置。
- 同一测试程序构建为 Windows x64，并在隔离 Wine 11.20 环境运行。
- 畸形 WAV、中文文件名、HRD 分段回复及错误头；强制结束解码进程后检查 GUI 和发射状态。
- 合成 FT8 音频 `CQ K1ABC FN20`，通过真实读取及解码进程验证输出。
- MCP HTTP 认证、Origin/Host 校验、请求边界、通知、只读和发射权限、stdio 桥接；官方 Python MCP SDK 2.3.0 的 HTTP/stdio 联调。
- AddressSanitizer/UndefinedBehaviorSanitizer 的 WSPR 译码边界与重复调用检查。
- 中文设置、呼号管理、关于 Logo 的截图检查；Windows 安装目录中全部非系统 PE 导入依赖解析。
- 用户私有参考日志只在隔离临时目录验证：12,065 条记录，12,035 条唯一通联，7 个季度文件；重复导入新增 0；原件 SHA-256 不变。原件、转换件和任何私有通联内容不进入源码及安装包。
- 中文路径安装、全部安装文件 SHA-256 对照；同路径升级；静默降级拒绝、交互降级“否/是”；卸载后保留用户文件、操作员日志及设置。

具体通过数量、安装包哈希和最终验收结果以交付目录的 `验证结果.txt` 为准；详细构建与测试输出保留在工作区 `logs/`。

## 实际使用限制

没有进行真实射频发射，没有连接用户的电台、Windows 声卡或 CAT/PTT 硬件。Wine 的虚拟音频环境不能替代 Windows 驱动测试。因驱动、时间同步、硬件掉线、操作系统或第三方 OmniRig/HRD/TCI 造成的问题仍可能存在，需要用异常时刻、配置、日志和复现步骤继续定位。

本次修复能覆盖已确认的若干闪退、停摆原因；没有用户原先故障的日志和复现条件，不能断言那些故障全部由这些原因引起，或已经全部消失。
