JTDX-F V3.7.0：结构整理与升级边界

本轮以 V3.6.6（963fea24ee6081f6740d8ef7e6a4e4825e9e0b0f）为基线，
选择移植官方 WSJT-X v3.3.0-beta5（d89fe30ca1dfd3c38def8f17228f09f042829f95）
的相关实现。不是把整个 JTDX 解码器替换为 WSJT-X，也不改变 FT8/FT4 空中协议。
参考：https://github.com/WSJTX/wsjtx/releases/tag/v3.3.0-beta5

一、组件来源

FT8/FT4 保留 JTDX 解码架构、既有 3.0.2 波形更新及现代解码开关，移植精选
beta5 频谱计算与并发修复，并修复本地共享状态、历史边界和模板写入问题。
pack77 和 AP 模板共同修复 RR73 的消息类型，拒绝 /R、/P 混搭时静默改写呼号。
JTTY 升至 beta5，并隔离实时/复核接收的历史；WSPR 保留 3.0.2 解码主体，
移植协议校验。Q65、MSK144、Echo 和天文计算仍为隔离的 3.0.2 helper。
各组件的精确来源及测试见对应 PROVENANCE 和本版本专项说明。
未加入上游 beta5 发布前已撤回的网络音频，也未恢复 CW 发号功能。

二、V3.6 六轮迭代的职责收拢

1. 设置与呈现：WSJTXGeneralSettings 管持久设置；本人消息配色、清空 DX
   和接收频率恢复继续沿用已验证入口。双击开启发射的新配置默认开启，
   已明确保存的关闭选择保留。启动程序、UDP 回复和内部回调不授予人工发射许可。
2. 目标选择：普通和托管共用 seedSelectedQsoHistory；完整呼号保留后缀，
   再次选择同一在途对象不能清零次数。双击/UDP 共用 managedSelectionBlocked；
   托管正在起发、发射或释放 PTT 时不能更换目标。UDP 只可利用已手工开启的会话。
3. 次数与候选：mainwindow_retry、mainwindow_busy 和 ManagedSession 分别
   管普通次数、忙台等待和托管策略。普通自动外呼冷却 8 分钟；来电仍可回答。
   托管按每种消息计次数，周期 CQ 累计 3 轮，来电可打断并在 QSO 后补足。
4. 收尾与日志：SignoffState 管完整波形、释放 PTT、接收机会和结束确认；
   日志可在 RR73/73 起发时保存，重发更新末轮时间，但不能提前更换对象。
   监管到时完成当前 QSO 或达到次数再停；人工停止和设备故障仍立即停。
5. 音频生命周期：beginAudioPlayback 统一分配轮次；音频完成/失败带同一
   generation。旧轮次的错误、源消费和排空事件不能终止新一轮。
   全双工接收缓冲在安全时统一应用，发射中切换不重启正在采集的声流。
6. 解码与外部接口：ft8_shared_state 统一实际 worker 分片、历史快照和
   结果发布；mainwindow_udp 单独负责有界历史、精确回复和分批重放。
   清除活动窗口同时清除历史并撤销未完成重放。保留 JTAlert 发现入口和 UDP 身份。

三、线程与性能设置

FT8 菜单保留“自动”，只显示 1 到当前 CPU 可用逻辑线程数的数值，且不超过
当前解码器支持的 24 线程。更高选项隐藏并禁用，迁移的超限手动值下调到上限。
检测不到处理器数量时保守使用 1。OpenMP 实际获得较少线程时，解码器按实际
数量分工；菜单限制不能替代这一运行时保护。
现代解码开关继续独立控制 FT8 和 FT4；CRC 和原始信道置信阈值未放宽。
资源测量与未采用的研究候选见 FT8 专项记录，不能把上游硬件上的加速比例
当作本机或用户电台的实测收益。

四、数据及验收边界

每个呼号的完整/季度双日志、缓存、old 原件、永久黑名单和临时退避保持独立。
导入长度兼容处理只用于外部文件，不放宽工作日志、事务日志或偏移定位解析。
NTP 的 UTC/权限流程、MCP 权限、停止保护和人工发射授权均保留。
相关回归覆盖 GUI、合成 PCM、Hamlib Dummy、实际本机 UDP 和隔离 Windows/Wine。
没有真实 RF、FT-450 实台、实体 Windows 声卡或宿主系统校时验收；Wine 与
Dummy 的成功不能替代这些现场测试。用户私有日志只作可选只读验证，不随包分发。
