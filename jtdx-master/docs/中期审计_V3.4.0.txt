JTDX-F V3.4.0 中期审计报告
团队：Fluxmancer
日期：2026-10-30
基线：JTDX-F V3.3.0，434b734001f4ef82ca1a9ed65b36f9554eee0c21
上游原版：JTDX 2.2.159

一、范围与方法

源码盘点（含上游实验/辅助代码）：99 个 C++ 源文件、83 个 C 源文件、362 个 Fortran 源文件（包含测试），另有头文件、界面、翻译及脚本。
审计覆盖主程序、C/C++ 与 Fortran 解码代码、音频输入输出、通联状态机、托管/监管、呼号与日志、MCP/UDP/TCI、CAT、NTP 权限助手、设置/中文、构建与安装打包。
采用全树 C/C++ 静态扫描、重点路径人工检查、Linux/Windows 编译、Qt 回归、真实合成音频解码、Fortran 数组边界检查，以及安装器升级/降级/用户文件保留验证。
静态扫描排除生成的 windows/omnirig 包装器和测试代码；这两部分仍参与编译/回归。Fortran 不是用 C++ 扫描器检查，而是结合源码检查、编译诊断及带 -fcheck=bounds 的实际解码验证。
不把静态告警数量当作 bug 数，也不把回归通过当作所有路径都无缺陷。完整审计指覆盖上述模块与交付链路，并不表示逐行形式化证明第三方代码。

二、本轮确认的问题和修复

A01 高：TCI 网络音频包缺少头部/载荷边界校验。
位置：TCITransceiver.cpp/.hpp。
修复：校验 64 字节头、类型、接收机、格式、采样率、样本数、偶数声道及实际载荷；限制 WebSocket 消息尺寸。异常立即报告并走停发射故障路径。
验证：短包、空包、非法头、声明 8192 样本但载荷不足的回归。

A02 高：TCI 发射长度把浮点数数量又乘以 2，可能越界读取源音频，并发送未初始化保留字段。
位置：TCITransceiver::txAudioData/onBinaryReceived。
修复：长度统一为浮点数数量，限制 1～8192 且为偶数；发送区先清零，确认连接有效。
验证：全树静态检查与两平台编译；实际 TCI 电台仍需实机验收。

A03 高：畸形 WAV/BWF 块长度可越界、分配超大元数据或错误寻址。
位置：Audio/BWFFile.cpp。
修复：使用 64 位边界运算，验证 RIFF、fmt、data、bext、LIST/INFO 内层长度及填充；元数据上限 16 MiB；PCM 读取和映射不越过 data 块。
验证：截断块、超大声明长度、短 fmt/bext、合法录音回读。

A04 中：BWF 固定长字段使用 strlen，缺少结束零时可能读越界；版本 getter 条件反向；扩展结构长度和大小端转换错误。
位置：Audio/BWFFile.cpp/.hpp。
修复：字段有界读取；扩展结构按 EBU 规范为 602 字节，时间字段 8 字节；16/32 位字段转换在副本完成；日期先转 UTC；只读 reset 不写文件，失败移动不无限循环。
验证：最大长度描述/来源字段、版本、UTC、时间参考、响度、编码历史，分别进行大小端文件往返。
规范：https://tech.ebu.ch/docs/tech/tech3285.pdf

A05 高：异步 WAV 保存直接引用持续写入的采集缓冲；切换/关闭时可能仍使用主窗口状态。
位置：AudioBuffer.hpp、Detector.cpp、mainwindow.cpp、TCITransceiver.cpp。
修复：保存前复制样本和 UTC/电台信息；采集、频谱读取和快照复制使用短时互斥；关闭等待在途文件任务；读 WAV 前先停止并排空实时采集任务。
验证：录音样本往返、长中文路径、UTC 元数据、连续实际解码与退出回归。

A06 中：WSPR 解码可能在异步 WAV 写完前启动，路径拼接也容易被空格影响。
位置：mainwindow.cpp。
修复：保存成功通知后启动 WSPR 解码，失败取消待解码状态；保存忙标记覆盖 finished 通知间隙；进程参数使用独立 QStringList；切换模式清除旧请求。
验证：编译、录音保存与解码回归；合成 -10 dB WSPR 音频通过真实 wsprd_jtdx 解码得到 K1ABC FN42 33。WSPR 实台接收留待硬件验收。

A07 中：GUI 直接修改音频线程的周期/频散参数，volatile 状态并不能提供线程同步。
位置：Modulator.hpp、Detector.hpp、mainwindow.cpp。
修复：参数通过队列信号在音频线程更新，GUI 查询发射状态改为原子变量。
验证：模式切换、手动授权/停止及新模式回归。

A08 中：调制器、TCI、瀑布图、显示对象部分状态在首次使用前未明确初始化。
位置：Modulator、TCITransceiver、plotter、displaytext、soundout、MessageServer、WSPRBandHopping。
修复：给全部相关标量安全初值，保留构造和后续设置覆盖。
验证：静态扫描、默认设置、启动/模式切换、图形截图。

A09 中：轮询电台控制在判断时钟指针为空前已解引用。
位置：PollingTransceiver::do_post_start。
修复：空指针时使用系统 UTC；正常情况下仍使用应用时钟。
验证：编译和电台生命周期回归。

A10 中：C2 文件名复制到 80 字节固定数组，Windows COM 设备名缓冲也过小。
位置：mainwindow.cpp、lib/savec2.f90、getfile.cpp。
修复：C2 路径使用动态 UTF-8 数组，检查长度/后缀/写入状态；COM 缓冲扩容并使用 snprintf。
验证：长中文录音路径、编译、Fortran 边界检查。

A11 中：外部 TCP 日志服务器无响应时，主线程同步等待连接/应答，表现为记录通联时卡住。
位置：LogForwarder.cpp/.hpp、logqso.cpp。
修复：异步连接/发送/接收，2.5 秒截止，ACK 分段拼接、NAK/断线/超大响应可见；失败不影响已经保存的本地日志。
验证：模拟日志服务器、延迟/分段 ACK、NAK，等待期间 GUI 定时器持续运行。

A12 中：WSPR 工具内存分配失败未处理，部分 C2 成功路径漏关文件/释放缓冲。
位置：lib/wsprd/wsprd.c、wsprd_exp.c、wsprsim.c；lib/ldpc/intio.c。
修复：检查分配/文件句柄，补齐成功和失败清理；修正 printf 参数类型。C2 名称按有界 14 字节写入；WSPR 消息补上字段、长度、网格、功率和复合呼号校验，移除临时堆分配，修正 4 字符网格补空格。
验证：静态检查、目标编译、WSPR 编解码内存回归；合法/畸形消息、短 C2 名称、10000 个固定种子输入，ASan/UBSan 与泄漏检查。

A13 低：方位辅助计算把毫秒按一天的秒数取模，得到错误时间。
位置：mainwindow.cpp 方位更新。
修复：先除以 1000 再按 86400 秒取模；其他毫秒周期计算保持不变。
验证：代码检查与两平台编译。

A14 中：FT4/FT2 波形缓存未把采样率纳入条件，12/48 kHz 交替使用可能取错缓存；前导空格移除循环可能截去消息。
位置：lib/ft4/gen_ft4wave.f90、genft4.f90；lib/ft2/gen_ft2wave.f90、genft2.f90。
修复：采样率/符号长度参与缓存判断；使用 adjustl；非法 FT2 消息清空音调。
验证：12→48→12 kHz 波形一致性、FT2 真正音频解码与 Fortran 数组越界检查。

A15 高：音频错误提示或退出过程中，停发射动作可能晚于阻塞对话框。
位置：mainwindow.cpp 音频错误/关闭、mainwindow_jtty.cpp。
修复：先撤销发射、取消待执行消息并释放 PTT，再提示错误/退出；JTTY 编码和延迟 PTT 回调再次校验人工许可、频率、呼号及监管。
验证：启动无许可、停止后旧回调、模式切换、故障停止、JTTY 取消编码回归；未接电台实际发射。

A16 中：日志导入/双份同步中的失败恢复及原件保护边界。
位置：OperatorLog.cpp。
修复：空垃圾文件不再作为空 ADIF 覆盖；提交前验证全部输入；季度记录优先并补空字段；混合呼号完整日志先备份原件再分流；归档前捕获源字节；追加失败回滚，部分提交可由下次并集合并恢复。Windows 回归发现原子替换前自身比较句柄未关闭导致 Access denied，已关闭读句柄再提交。
验证：旧碎片、完整日志、双向缺失、重复、不完整记录、冲突字段、二次同步不重写、写入失败、混合呼号原件保护；私有参考日志仅在隔离目录验证。

A17 中：监管超时直接停止会打断当前 QSO，旧重试清理分支还可能在一帧发射途中清空对象。
位置：mainwindow.cpp、mainwindow_mcp.cpp。
修复：到期只允许捕获的当前呼号/模式/频率继续；最后 73/RR73 实际发完或超次数后停止，不接新对象/CQ；手动停止/故障不延迟；计数清理等待 PTT 释放。
验证：普通/托管收尾、禁止新 QSO、人工立即停止、跨通联计时与 0 分钟不限时回归。

A18 低：托管状态标签与临时状态消息重叠，QSO 爱好者标题遗漏说明；JTTY 提示文字在较小窗口裁切。
位置：mainwindow.cpp、ManagedSettings.cpp、mainwindow_jtty.cpp、中文翻译。
修复：临时状态消息期间隐藏托管标签；补完整标题；调整键盘模式提示长度与布局。
验证：中文截图检查和界面回归。

三、本轮功能一致性检查

1. 每个呼号的季度主日志与 wsjtx_log.adi 保持记录并集；主程序查重只读季度文件。完整文件一直放在呼号目录，不移入 old。外来原件保护不变，删除呼号不删除数据。
2. FT2 是 Decodium 3.75 秒 4-GFSK 协议，实际编码/解码；不是只增加菜单名。JTTY 采用 WSJT-X 键盘协议，独立子进程处理有界音频/JSON 消息，逐条人工发送。
3. 两个新模式按 MFSK/SUBMODE 写入 ADIF 3.1.8；预置频率取自固定上游提交。来源/许可证见 lib/ft2/PROVENANCE.txt、lib/jtty/PROVENANCE.txt。
4. MCP 共 22 工具；新增 JTTY 文本准备不直接授权发射。只监听本机、令牌、输入长度/范围、修改和发射权限、人工发射许可仍分层校验。
5. 托管每次启动关闭；人工停止后定时 CQ/UDP/MCP/延迟任务不能恢复发射。NTP 使用 UTC，发射期间暂缓，权限助手无任意命令执行入口。
6. Windows 独立产品标识、中文降级提示、升级/卸载保留日志，GPL/原贡献者/Fluxmancer/Logo 与来源文件纳入发行审查。

四、验证结果

最终计数和原始输出见发行目录“验证结果.txt”与“验证日志”。测试包含初始化/清理；Windows 的私有日志测试跳过，Linux 使用用户提供的原件只读验证。
调试过程中曾出现：总回归在并行编译负载下超过旧 90 秒限制、旧状态复用造成测试夹具冲突，以及 WAV 元数据解析修订导致的保存字典丢失；已分别延长合理测试预算、隔离夹具、修复字典处理并重跑。

五、边界与后续实机验收

本轮已修复上述确认问题。没有证据可以承诺“原来所有卡住/闪退都已消除”，也没有任何一次审计能证明项目永远无未知缺陷。
Windows 使用隔离 Wine 验证程序与安装器；未进行 Windows 声卡、CAT/PTT、真实 UAC/Polkit 校时、实台 TCI 音频、射频或长时间硬件压力验收。测试不发射射频，不修改宿主时钟。
FT2/JTTY 当前使用本机音频；TCI 音频会在发射前明确拒绝，CAT 控制可用。JTTY 是逐条键盘通联，不使用 AutoSeq/托管；FT2 多周期平均解码未启用。这些是已说明的功能边界，不冒充完成的硬件能力。
监管到期后如呼叫次数设置为 0（不限），当前 QSO 的等待仍无次数上限；人工停止始终立即生效。
双份日志采用取并集语义：只在一份删除的记录会被另一份补回；外部日志软件兼容新模式取决于其 ADIF 版本。
用户私有日志及其转换内容不进入任何程序/源码发行包。原件 SHA-256 在交付审计中复核。
