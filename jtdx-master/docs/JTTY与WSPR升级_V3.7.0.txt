JTDX-F V3.7.0：JTTY 与 WSPR 升级、边界与验证

参考版本
WSJT-X v3.3.0-beta5，官方仓库 https://github.com/WSJTX/wsjtx
固定提交 d89fe30ca1dfd3c38def8f17228f09f042829f95。
JTTY 基础来自 beta4；本次更新多信号解码器和 TBCC 列表解码器。
WSPR 主解码器基础仍是 v3.0.2；本次更新消息解包、格式化及哈希读取工具。
准确来源分别记录在 lib/jtty/PROVENANCE.txt 和 lib/wsprd/PROVENANCE.txt。

实现
1. JTTY 增加已确认帧的短期参考，过滤强信号在整符号时间偏移处形成的伪帧。
   同频附近的真实弱台仍可独立解码，已减去的干扰帧不重复施加过滤。
2. TBCC 序列能量计算复用公共前缀，并将最后四个候选音的计算合并，便于编译器
   向量化。保持原有编码、CRC、候选顺序及数值判定语义。
3. beta5 新增的 alias 历史属于接收上下文；本地将其纳入已有 receive_state
   交换及重置，防止实时监听、手动复核互相污染，或停止一个会话清除另一个。
   这沿用原有上下文机制，不另建分散的会话补丁。
4. WSPR 非法后缀编码不再因 char 截断变成合法呼号；保留类型 63 明确拒绝。
   解码失败不会污染呼号/网格缓存，也不会把上一个消息当作新消息发布。
5. WSPR 共享有界格式化和哈希行解析，拒绝越界索引、超长呼号/网格及数字溢出；
   缺少网格的旧哈希记录继续保留已知网格。沿用 JTDX-F 的坏哈希槽保护、负数
   网格校验、WAV/C2、Fano 和仿真输入安全修复。

验证入口
cmake --build build --target fm_jtty_alias_decode fm_jtty_tbcc_list_decoder \
  fm_jtty_alias_context fm_wspr_unpack
ctest --test-dir build --output-on-failure -R 'fm_jtty_|Wspr'

测试目的
- alias_decode：24 组固定噪声种子下的强信号误帧回归，以及相邻弱台真实重叠。
- tbcc_list_decoder：优化与参考算法在相干长度、候选宽度、同分及大公共能量下
  的一致性，并检查 CRC、保留位、工作区及候选接口契约。
- alias_context：合成 PCM 在实时/复核上下文间交错处理，停止、重新开始及销毁
  后仍各自完整解码，且不改动独立解码器已有的参考历史。
- WsprUnpack：合法消息、后缀边界、保留类型、无效输入后的缓存保持、哈希行、
  坏哈希槽和负数边界；继续运行已有 WSPR 编解码、文件和波形测试。

性能与范围
TBCC 优化旨在减少计算，不增加搜索深度；alias 检查最多保存 32 个 59 音参考帧，
每个接收上下文约增加 8 KiB 历史。不能据此声称固定的灵敏度提升或全机提速。
若进行旧/新计时，应使用相同合成 PCM、参数、编译器和线程设置，多次交错运行，
同时记录完整解码/误帧数及 CPU 时间；强信号误帧被消除会改变后续搜索工作量。
所有回归使用公开测试消息和合成音频，不访问真实电台或操作员私人日志。

实际验证（2026-10-31）
在隔离目录编译三个新 JTTY 单元，与冻结的其余生产静态库链接；上述五项 JTTY
回归（包括原有 receive_state、continuous_decode）全部通过。相同 24 组噪声
PCM，新旧版本都完整解码 24/24；旧版 4 组额外报出错误消息，新版 0 组。
这是特定可复现误帧的修复证据，不是实台全场景误码率或弱信号门限结论。
WsprUnpack 普通构建和 AddressSanitizer/UndefinedBehaviorSanitizer 构建均通过。
同一负对照探针：旧版将 suffix 60256/60283 误当作 /0、/R，并把保留类型 63
返回成功（输出仍为上一条消息）；新版均拒绝。正常后缀与合法哈希消息继续通过。
详细日志、冻结旧库及复现脚本保存在工作区 .qa/v370-jtty-wspr/。
