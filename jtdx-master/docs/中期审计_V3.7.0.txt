JTDX-F V3.7.0 中期审计
团队：Fluxmancer
审计日期：2026-11-01

一、结论及审计范围

本轮按 WSJT-X v3.3.0-beta5 选择移植解码、并发、CAT、音频和 UDP 修复，
并整理 V3.6 系列连续迭代的共用入口。追加协议兼容性检查前的阶段测试为
Linux 全套 48/48 组通过、Windows/Wine 可执行测试 41/41 组通过。
随后同 PCM 负对照发现并修复旧 RR73 弱信号 hint 接收回退，完整 PCM
与噪声验证已通过；详情见第四节。最终封包检查另行记录，这些有限测试
不表示不存在未知问题。

行为基线：V3.6.6，963fea24ee6081f6740d8ef7e6a4e4825e9e0b0f。
上游参考：WSJT-X v3.3.0-beta5，d89fe30ca1dfd3c38def8f17228f09f042829f95。
本报告形成时尚未封包；最终提交、干净构建、安装验收和交付物 SHA256
由发行清单-V3.7.0.json、SHA256SUMS-V3.7.0.txt 及随包验证结果确定。

实际升级边界：
- FT8/FT4 保留 JTDX 架构与既有 WSJT-X 3.0.2 协议/波形更新，引入精选
  beta5 性能与并发改进；Fluxmancer 现代解码开关独立保留。
- JTTY 解码与列表译码移至 beta5；增加本地实时/复核历史隔离。
- WSPR 保留 3.0.2 解码主体，移植 beta5 消息有效性校验及本地边界修复。
- Q65、MSK144、Echo、天文 helper 仍为隔离的 3.0.2 实现；FT2、SuperFox
  沿用已有独立集成。没有加入受限 SuperFox 表或已撤回的网络音频。
- Hamlib 继续使用支持的 4.7.2 ABI。本轮不是 Hamlib 5 运行库迁移。

二、发现并修复的问题

1. FT8 频谱与内存安全
   改用只计算所需 8 个频点的符号频谱，修复正向谱临时数组未初始化、
   反向谱每个符号复制整张矩阵，以及静音端点 0/0。修复 ft8s 的 77 字节
   输出被写入隐式标量、worker 接收消息缓存越界和共享 hint 模板写入。

2. FT8 多线程分工及共享状态
   24 套分发合为按 OpenMP 实际线程数分片的入口；解决请求线程多于
   实际线程时 barrier 无法会合的问题。去重和发布成为同一原子过程，
   130 条历史容量有界，通联历史读写使用一致快照。长 FFT 缓存线程私有，
   残差信号快照与信号减除同步，防止交叉污染或覆盖。
   FFTW 计划创建、查找和销毁共用锁，通用计划显式单线程，避免切换
   JT9/T10 后叠加 worker×FFTW 线程。FFT 执行仍在计划锁外。

3. 呼号身份、AP 与 77 位协议
   完整 token 匹配取代呼号子串匹配，不混淆相近呼号及 /R、/P 后缀。
   /P 的 Type2 AP 位与真实编码一致；换呼号/网格使旧缓存失效，拒绝
   99、0 或非有限 pin 标记。已知消息的类型位在进入 BP 前统一处理。
   RR73 发射使用标准尾部值 32403；接收根据原始符号能量选择标准或
   旧 32373 模板，保留弱信号兼容，不增加候选编号及 BP/OSD 次数。
   CQ RR73 和明确的
   R+网格继续表达真实网格。/R、/P 混搭不能由同一
   Type1/2 suffix 表达时使用既有自由文本回退，避免静默改写呼号。

4. 现代 FT8/FT4 rescue 的计算安排
   BP→OSD 改为逐条计算 posterior 并立即尝试，前一条成功时不再计算
   后续轨迹。候选顺序、最多 6 次 OSD、CRC14、重编码及原始信道证据
   门槛保持不变。研究候选没有显著可靠收益，未装入产品，详见第五节。

5. JTTY 强信号伪帧与接收上下文
   beta5 的频移 alias 过滤排除强信号产生的伪帧，保留真实弱重叠台站；
   列表译码减少重复能量计算并采用连续数据布局。新增 alias 历史随本地
   receive_state 交换和复位，防止实时监听与人工复核互相抑制。

6. WSPR 非法消息和哈希边界
   后缀差值改用足够宽的整数，防止字符截断把非法后缀变成合法 /0、/R。
   保留类型 63 不再返回成功并沿用上一条文本。统一哈希文件行解析，
   限制字段长度，拒绝负值、坏网格、损坏或未终止哈希条目；保留之前
   的经度回绕、边界和内存安全修复。

7. CAT 分离操作的首发模式和 VFO
   RX/TX 角色覆盖 A/B 与 MAIN/SUB，发射时不被临时活动 VFO 改写。
   换频可能调出波段记忆时绕过并恢复模式缓存，在真正的 TX VFO 上
   校正数字边带；DATA1/2/3 保留兼容配置。模式校正失败不进入 PTT。
   同一状态请求同时改变 RX/TX 时两边均落实，修复旧 else-if 漏掉 TX。

8. 全双工接收和音频异常生命周期
   全双工采用 48,000 帧接收缓冲，半双工保留 Qt 默认，显式环境设置
   优先；在安全时机应用，不在发射中重启采集。停止、替换、格式错误
   和后端错误共用失效/停止路径，先关闭旧输出再报告错误。
   消费、排空和失败都携带播放轮次；旧回调不能结束新一轮，正常 PCM
   EOF 与真正欠载分开。当前音频故障撤销发射许可，不自动重新发射。

9. UDP 连接、输入校验和资源边界
   过期 DNS 查找撤销且回调验证轮次，待解析队列限制 128 条/256 KiB，
   换目标或端口清空旧队列及去重状态。每批处理最多 64 个数据包后
   让出事件循环。UDP socket 显式 NoProxy，修复 HTTP/系统代理使
   本地绑定失败、进而无法与 JTAlert 通信的问题。
   Reply 要求六个原始身份字段完整，兼容两个可选尾字段；截断命令
   被拒绝，TriggerCQ 的两个布尔参数按协议顺序读取。

10. UDP 回复与历史重放
    通过有界结构化历史精确匹配时间、SNR、DT、音频频率、模式和消息；
    不因界面隐藏普通已通联消息就丢失可回复记录。WSPR 保存逐条 offAir。
    清除/换上下文撤销旧重放，移除从残留 UI 文本重建历史的回退；分批
    重放允许停止及其他事件执行。新加入永久黑名单的缓存记录不可回复。
    UDP 与双击共用托管发射期间的禁止换台保护；远程选择只能使用已有
    人工发射许可，不能由 UDP 自行赋予启动权限。

11. 外部 ADIF Unicode 长度兼容
    外部导入同时兼容字符数与部分软件写入的 UTF-8 字节数长度；只在
    字段端点明确截断标签或越界、且可由有效 UTF-8 长度恢复时转换。
    修复两条 QSO 被误合并及坏 ASCII 长度吞掉后续字段的问题。
    内部工作日志、事务日志和修改偏移仍严格解析；不猜测损坏记录。
    原件保持字节不变备份至 old，双日志同步、更新定位及重复导入均回归。

12. 默认值、线程菜单和版本说明
    双击呼号启用发射的新配置默认开启，已保存 false 仍保留；软件启动
    不因此获得发射许可。FT8 菜单上限为可用逻辑线程数与 24 的较小值，
    未知 CPU 数用 1，保留自动档，迁移超限手工值下调。统一触发入口
    同时检查可见和可用状态，防止程序触发隐藏 QAction 绕过限制。
    关于页面明确各模式实际来源，相关文案同步 19 种语言，避免把整个
    解码器描述成 beta5。全部语言 XML 和 lrelease 检查通过。

三、V3.6 功能保留及重复逻辑整理

普通与托管的选台共用 seedSelectedQsoHistory；重复选择同一在途目标不能
清零次数。mainwindow_retry、mainwindow_busy、ManagedSession 分别管理
普通次数、忙台等待和托管策略，SignoffState 管收尾。GUI 回归覆盖：
- 两种托管模式每条消息的次数限制、失败退避、周期 CQ 被来电打断后补足；
- 普通外呼失败后的 8 分钟冷却、来电仍回答、等待目标 CQ/结束消息后恢复；
- RR73/73 完整发送、接收机会和确认，提前记日志但不提前换台，末轮更新；
- 监管到时完成当前 QSO 或达到次数后停止，人工停止及设备故障立即停止；
- 托管人工双击选择、时序规则、旧解码候选不被再次当作新来电；
- 本人消息配色、DX 清理、频率/波段同步及双击的发射授权边界。

呼号独立的完整/季度双日志、切换缓存、old 原件与永久黑名单继续保留；
永久黑名单与托管临时退避不混用。NTP UTC/权限流程、MCP 权限、JTAlert
兼容身份与发现入口保留。删除的 CW 发号功能没有恢复。

- WSPR 旧库错误接纳两个非法后缀，类型 63 返回旧消息；新版拒绝。

- FT8 旧库在实际线程 3、请求 8 时的完整 pass 负对照超时；新版实际
  1/2/3 线程均恢复全部 6 个合成台站。更多对照见 FT8 专项记录。

追加兼容性缺陷及修正：
标准 RR73 尾部修正后，以完全相同 PCM 输入对照旧 V3.6.6 发出的 32373
结束消息，弱信号 hint 接收曾由 24/24 降为 12/24；-22/-24 dB 的 12 例
丢失。普通解包兼容不足以证明 AP 兼容，此负对照已保留。
接收端现根据原始符号能量选择标准/旧 RR73 模板，不增加 BP/OSD 次数或
放宽信道阈值；发射仍使用标准 32403。旧编码 PCM 已恢复 24/24；标准编码
PCM 新接收器也为 24/24。两版接收器各 40 帧已知呼号纯噪声/单音噪声均
为 0 解码。两种 RR73 与噪声案例已加入持续回归。旧接收器对标准编码的
弱信号 AP 仍只有 12/24，不能远程修复对端，也不宣称所有旧对端表现不变。
最终干净构建与全套复测的结果由发行清单、版本专属验证目录记录。

五、性能、现代算法探索及限制

性能和资源只引用 docs/FT8_V370_VALIDATION.md 及其逐帧/PCM 原始记录。
已移植所需频点计算、减少重复拷贝和安全并发；不能由单个内核改进推导
整机统一加速百分比，更多线程也不保证更快。现代开关只影响可选 rescue，
公共内存和并发修复同时用于传统路径。FT4 本地路径仍串行。

本轮考察 Adaptive Learned BP 与 Row-Boosted Ensemble BP，并在相同
OSD 预算和原始证据阈值下筛选有限候选。没有足够稳定收益支持替换，
故研究代码不链接生产程序。现有现代算法保留；不宣称新的 dB 增益、
普遍更低误码率或已达到零误码。JTTY 有限样本的改善也不能外推为实收保证。

尚需现场验证：原生 Windows 长时间运行、真实声卡错误/全双工、FT-450
及其他电台 CAT/PTT、SWR、卫星/EME 链路、JTAlert 2.81.7 实际互操作。
本轮未发射 RF、未操作实体电台、未执行宿主系统校时。Wine、Dummy、
本机 UDP 与合成 PCM 能验证代码分支，不能代替这些硬件及应用验收。
非标准 hashed 呼号与 /P 混合的旧 AP 限制保留，普通无 hint 路径仍可尝试。
