JTDX-F V3.6.6 本轮修复说明

1. 恢复 JTAlert 所依赖的程序发现信息
现场反馈为 JTAlert 2.81.7 可以连接原版 JTDX 2.2.159，但无法连接 JTDX-F。源码确认此前分支改变了进程名称、窗口标题格式、UDP 实例身份和配置位置。另一个 JTDX 分支作者的实际诊断显示，JTAlert 会查找 jtdx.exe，并根据窗口标题里的实例名寻找对应 INI；将团队署名放在版本之前会导致查找错误配置。这是本轮修复的依据，但还没有用户现场诊断证明每个差异分别造成了哪一步失败。

Windows 实际主程序恢复为 JTDX-F 自己安装目录中的 jtdx.exe，原 jtdx-f.exe 保留为启动器，旧快捷方式及启动路径继续转交到主程序。窗口标题和主 UDP 接口采用 JTDX - JTDX-F 实例身份，版本仍如实显示 v3.6.6，Fluxmancer 团队署名移到版本号之后。没有将产品改回原版 JTDX，也没有伪造为 2.2.159。

2. 保持独立配置、日志与发现信息一致
应用主配置仍属于 JTDX-F；不读取或迁移原版 JTDX 的工作配置。额外在 Windows 的 %LOCALAPPDATA%\JTDX - JTDX-F\JTDX - JTDX-F.ini 写入供 JTAlert 发现使用的少量配置，限 UDP 配置、呼号和网格等白名单字段，不复制 CAT/PTT、声卡、日志或 MCP 令牌。
投影带有归属标记，只更新本分支创建的文件，不覆盖陌生文件；内容不读回工作配置。保存相关设置及更换操作员后同步更新，以免 JTAlert 使用过时的端口、呼号或网格。已有 UDP 地址、端口和接受请求选项继续保留，不在升级时强制更改。
多实例名称保持一致，例如 --rig-name=FT450 的主应用仍为 JTDX-F - FT450，窗口、UDP 实例及发现配置名则使用 JTDX - JTDX-F - FT450，避免不同实例共用同一个发现文件。

3. 修正 FT4 等模式的 UDP 回复时间格式
原 UDP 回复代码只针对部分模式标记生成六位 HHMMSS。FT4 使用 + 标记，可能被重建为四位 HHMM，与界面的原解码行不一致，造成收到请求后仍找不到目标消息。现在按实际工作模式选择时间格式，FT 系列和使用秒时间的上游模式使用六位，其余旧分钟制模式沿用四位；原有 ~ 和 : 标记的六位处理保留。
该修正也覆盖本分支 FT2 的回复路径；不据此声称 JTAlert 已识别或支持 FT2。收到 UDP 请求仍检查接受选项、允许的消息类型、可见原解码和正常通联状态，不把外部请求当作本机人工双击授权。

4. 连接方法与发射约束
先启动 JTDX-F，再启动 JTAlert for JTDX。新配置的主 UDP 默认 127.0.0.1:2237；两端应使用匹配设置。需要第三方点击回复时，由操作员勾选接受 UDP 请求并选择允许的消息类型；仅显示解码和状态不依赖此开关。修改地址或端口后重启 JTAlert。原版 JTDX 与 JTDX-F 同时使用时，应分别配置端口并核对实例。
第三方回复请求不能将已经停止的会话重新授权为发射；仍须先由操作员在 JTDX-F 启用发射。已有会话继续遵守监管、黑名单及收发限制，不因兼容 JTAlert 绕过安全状态。

5. 降级到 V3.6.5 及更早版本的发行边界
V3.6.6 在 Windows 安装目录新增实际主程序 bin\jtdx.exe，旧 bin\jtdx-f.exe 保留为启动器。已发行的旧安装器只覆盖其知道的文件，直接安装旧包不会删除新增的 jtdx.exe；JTAlert 若仍通过该路径自动启动，可能启动残留新版。
因此，降到 V3.6.5 及更早版本时，建议先卸载 V3.6.6，再安装旧包，并将第三方启动入口改回旧版 jtdx-f.exe。卸载保留独立用户数据目录中的日志和设置，不需要删除这些数据。本轮没有验证旧包直接覆盖能完成全部文件的降级，也没有修改已发行的旧安装包。

验证记录与限制
本说明描述本轮实现；最终构建、专项回归及安装结果以本版交付验证资料为准。UDP 回环测试和模拟 GUI 操作只能证明本分支的协议收发与状态处理，不能替代 JTAlert 本体的连接测试。
专项覆盖包括：实例 ID 与窗口标题、发现文件白名单及归属保护、真实本机 UDP 数据包收发、FT8/FT4/FT2 回复定位、已人工启用时选台，以及未授权或停止后不能由第三方重新开启发射。是否通过以最终记录为准，不预先将待执行检查记为通过。
官方 JTAlert 安装包下载返回 HTTP 403，本轮未实际运行用户所用的 JTAlert 2.81.7，也未连接实体电台或进行射频发射。因此不宣称 JTAlert 2.81.7 已实机验收；用户安装后仍需确认程序发现、解码显示和已授权会话中的点击回复。
